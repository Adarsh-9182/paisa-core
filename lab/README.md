# The Paisa narrator lab

*Fine-tune a small open-weight model into a Paisa narrator, on your own
machine, graded by Paisa's own verifier. Per the first engineering rule
(NORTH_STAR, 2026-07-11): Claude built this harness; the training runs,
the tuning decisions, and the eval methodology are yours.*

## What you're training, precisely

Not knowledge — behaviour (the Sonar lesson, spec 007). The model learns to
answer a financial question **using only the tool results in its prompt**,
quoting every figure verbatim, citing sources for law. The training data is
generated by the deterministic engine, so every example is correct by
construction; the grader is `verifyNarration`, the same function production
uses. Facts stay in the engine; the model learns to be honest with them.

## Setup (once)

Already done in this repo: `lab/.venv` with `mlx-lm 0.29.1` (Apple-Silicon
training stack). Rebuild core if you changed it: `npm run build`.

## The loop

```zsh
# 1. Generate training data (4000 train / 400 valid, seeded, ~1s)
node lab/generate-data.mjs

# 2. Train — first run downloads the base model (~1.9 GB)
./lab/train.sh                       # knobs: ITERS, LR, LAYERS, BATCH, MODEL

# 3. Serve the adapter locally (OpenAI-compatible API)
lab/.venv/bin/mlx_lm.server --model mlx-community/Qwen2.5-3B-Instruct-4bit \
  --adapter-path lab/adapters/paisa-narrator-v0 --port 8080

# 4. Grade it with the verifier (held-out seed — never train on 424242)
node lab/eval.mjs 40
```

**Baseline first:** run steps 3–4 *without* `--adapter-path` before your
first training run. That number — the untuned model's verifier pass rate —
is what your fine-tune has to beat. Write it down.

## Wiring a good adapter into the app

The provider chain already speaks OpenAI. Point it at your local server:

```zsh
# in web/.env.local
OPENAI_API_KEY=local
OPENAI_BASE_URL=http://localhost:8080/v1
```

Restart the dev server and the chain becomes Fable 5 → **your model** →
planner. Every answer still passes through `verifyNarration` — a weak
narrator degrades gracefully, it never lies undetected.

## What to learn (and where it lives)

- **Loss vs verifier pass rate** — they diverge; when and why?
- **Overfitting on formulaic data** — the planner's phrasing is rigid; does
  the model parrot structure or generalize to unseen scenario mixes?
- **Eval methodology** — `lab/eval.mjs` is a skeleton on purpose. Per-scenario
  breakdowns, citation-presence checks for regulation answers, style scoring,
  paired baseline/adapter comparisons: build them.
- **Data quality ceiling** — synthetic data teaches structure, not judgment.
  The premium corpus is real Fable-answered conversations via
  `auditRecordToExample` — which needs the prod API key you still owe the app.
